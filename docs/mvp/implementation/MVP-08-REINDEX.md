# Held recovery reindex for a restored Managed KB generation

If a restored database marks a generation active but its exact curated artifacts are absent from the Managed Knowledge Base, keep `PROPOSAL_PUBLICATION_HOLD=true`. Reconcile the decision audit and any exclusions made after the backup. Restore matching immutable curated blobs and inspect the current plan before proceeding. The hold blocks retrieval, pinning, and drafting reuse while this work is incomplete.

Run `reconcile_publication <generation-uuid> --reindex-active` to prepare that generation. Preparation requires an active Managed KB generation, a current exact plan and artifact set, no deletion marker, no competing staged/indexing/verified generation, and the hold. It does not call AWS. It fences the old active mapping by moving it to `staged`, resets prior ingestion status, and writes an audit event. A rejected preparation leaves the active row unchanged and the hold in force.

While the hold remains on, run `reconcile_publication <generation-uuid>` repeatedly. The existing publisher checks the KB's curated S3 scope, verifies local blob hashes, reuploads immutable curated bytes, starts or observes ingestion, and requires each expected S3 URI to report `INDEXED`. A transient failure may be retried with the same command. An interrupted attempt can resume from its persisted generation state. At `verified`, the generation remains unavailable because the hold blocks activation and application retrieval. Inspect the exact index statuses, current decisions, citation mappings, and any newer exclusions. Keep the hold on for any discrepancy.

Finally run `reconcile_publication <generation-uuid> --activate-reindexed` **while the hold is still on**. This requires the preparation audit event and verified state, and rechecks the current plan under the existing activation locks. An accidentally cleared hold still cannot autoactivate a prepared recovery generation; restore the hold before this explicit step. Only after successful activation and recovery reconciliation should the operator clear the publication hold. This action is distinct from `--restore`, which handles eligible retired generations that are already exactly indexed. Do not clear the hold to make an incomplete reindex progress.

The local synthetic suite covers missing-index recovery, exact verification before explicit activation, upload failure and retry, rejection without a hold, competing work, and a newer exclusion. Live Managed KB behavior, source/decision history reconciliation, restore timing, and actual cost remain MVP-08 live checks.
