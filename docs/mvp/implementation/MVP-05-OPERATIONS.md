# MVP-05 curation and comparison operator guide

Apply migrations `0011`–`0016` after backing up retained PostgreSQL and object storage. These migrations retain earlier decision events, units, citations, and artifacts; `0011` marks earlier decisions with recorded events as resolved, and `0016` enforces one current curation plan per family/version. New classification facts distinguish source role, authorship, version status, content use, claim type, chemistry, conditions, temporal meaning, treatment, and sensitivity. An unknown chemistry or condition remains JSON null. A path name is never evidence of authorship or submission.

Open **Scoped curation review** from an authenticated collection. The first page shows up to ten unresolved questions; **Show the complete set** exposes every remaining question. Critical questions remain stored and block only their applicable family/version/section/unit/entity passages, even if omitted from the first ten. Open a decision to see the recommendation, source excerpts, affected records, scope, consequence, and prior events. Approve, edit, defer, reject, or undo using the current revision. Concurrent stale forms receive HTTP 409. A rejection without an alternative leaves the issue unresolved. A deferral leaves a critical gate in place. Voice approval requires an explicit human edit; factual inclusion never grants it implicitly.

Partial treatment stores selected extracted-unit IDs. Summary treatment stores source-unit IDs, reviewer text, and `voice_eligible=false`. The `curation.build_plan` service produces a versioned plan listing factual eligible units, voice-only approved units, excluded units, and derived summaries. No unknown passage is eligible. Sensitive policy facts prohibit inclusion regardless of a narrower treatment answer. Each new fact or scoped decision invalidates its dependent plan and makes affected current local artifacts ineligible immediately. Historical citation rows and prior decision events remain. MVP-06 will render the plan into immutable excerpt bytes and reconcile the external index; this PR does not claim that a plan is already a published S3/KB artifact.

For reproducible synthetic comparison, create a local collection and an allowlisted local user using the existing operator flow, then run:

```powershell
& '.venv\Scripts\python.exe' scripts/manage.py evaluate_curation --collection '<collection-uuid>' --user '<allowlisted-username>' --cases sample_data/application_slice/curation_eval.json --mock
```

This runs the same bounded case list through three **fictional response fixtures** and stores one `EvaluationRun` with three `EvaluationRecord` rows. It prints aggregate metrics and a run ID, never excerpts. The results prove harness mechanics only. For private calibration in MVP-09, create a private JSON file with the same `cases` fields, real source-version and unit UUIDs, and `split` values `calibration`, `frozen`, or `expansion`. Group equivalent proposal versions and duplicates under one `group` so they cannot cross splits. Keep the labeled file and any full result export in private storage. The command checks that private unit/version IDs belong to the collection. It compares identical ordered cases and records abstentions, false exclusions, contamination, claim-type accuracy, confidence bins, review burden, latency, model revision, token usage, and reserved cost. Missing confidence abstains; model output never applies a destructive exclusion automatically. A small synthetic score is not a threshold or a model-selection decision.

Live use requires `--live --max-spend-usd <cap>`, configured per-call estimates for all intended routes, available provider credentials, and the cost envelope in the setup checklist. The economical Bedrock inference profile ID remains unconfigured until an actual affordable candidate is selected. The baseline uses the repository's configured Bedrock inference profile. The Jev route additionally requires `TYPESAFE_API_KEY`, `classification_routes.jev.enabled: true`, the privately recorded TypeSafe transfer decision, and `PROPOSAL_JEV_PRIVATE_TRANSFER_APPROVED=true` for every live Jev request. A caller-supplied `synthetic` label cannot waive this gate. Missing settings leave that route unavailable in the result. The caller must set an AWS profile or workload role externally; credentials never enter Git or browser payloads. The comparison harness reserves its estimates before calls and counts uncertain provider outcomes conservatively; reconcile gross charges against provider billing before claiming actual cost. No provider call is made in ordinary tests.

If a decision must be reversed, use **Undo last answer**. It appends a compensating event, recalculates the effective inherited value, and invalidates dependent work. Do not delete decision history or manually reactivate old artifacts. If reverting deployment code, stop new curation/publication activity and restore database/object storage in isolation from a verified backup. Replay newer exclusion events or keep publication disabled until reconciled. Do not roll back a live schema to `0010` while new curation rows are retained.
