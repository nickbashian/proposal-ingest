## Design and boundaries

Publication builds one text object per eligible factual unit or source-backed human summary. A partial treatment selects only its named units; metadata-only, excluded, pending, and voice units produce no KB text object. Every object has a content hash, source version, source unit IDs, locator, treatment decision event, and generation. The S3 key uses only generation and artifact UUIDs. The metadata sidecar contains bounded string identifiers and a hash, with no source text or path. Original source snapshots remain in local object storage outside the `curated/` KB prefix.

The Managed KB adapter verifies that its data source is available, points at the configured private bucket, and has exactly the configured curated inclusion prefix before uploading or starting ingestion. It uploads the curated text and sidecar with server-side encryption, starts an idempotent ingestion job, polls its status, and asks `GetKnowledgeBaseDocuments` for **each expected S3 URI**. A `COMPLETE` job or aggregate count alone cannot activate a generation; every document must report `INDEXED`. Failed or partially indexed documents leave the previous generation active and the new generation failed. Missing or still pending per-document statuses remain pending until the configured reconciliation timeout. Retries keep the old job ID for a distinct new client token while an uncertain start without an ID reuses its token.

Activation locks the proposal, recomputes current plan and source eligibility, checks the staged generation fingerprint and expected artifact set, then retires the prior active generation atomically. A source version change, retirement, exclusion, policy revision, or human correction blocks stale activation and application use immediately. Managed retrieval snapshots active generation IDs, ignores provider text, verifies result artifact ID, generation ID, hash, and S3 URI against application mappings, and reloads exact curated bytes. Pins, saved packet reuse, local search, and drafting use the same eligibility service. Drafting rechecks after the call before saving a revision. Historical citations remain readable but are marked withdrawn.

`PROPOSAL_PUBLICATION_HOLD=true` closes retrieval, pinning, drafting reuse, staging, and activation during a restore until source/decision audit and index reconciliation are complete. Unknown KB objects are rejected. A retired generation can be restored only if it still matches current decisions and its exact objects are verified; otherwise it remains unavailable. Retired S3 bytes can be deleted and the deletion sync checked by exact `NOT_FOUND` statuses. Deletion lag does not grant application membership.

## Verification and limits

The local Python 3.13 environment passed Black, Ruff, codespell, mypy, secrets, configuration shape, Django system checks, and migration autodetection. The focused SQLite override passed 52 MVP-05/05b/06 tests with one PostgreSQL-only source-sync demo skipped. The final full SQLite override check passed **532 tests**, skipped that one demo, and failed **20 preexisting PostgreSQL-specific tests** that require database triggers/advisory locks or child processes. The separately invoked browser smoke, mock pipeline, and secrets scan passed. A final `make check` and hosted PostgreSQL CI result belong on the PR. Local Docker Desktop had no Linux engine; no PostgreSQL service was available to this worktree. No AWS credentials or live KB were used.

The S3/Managed KB contract follows the current AWS [managed KB S3 source](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-managed-ds-s3.html), [ingestion job](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent_StartIngestionJob.html), [per-document lookup](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent_GetKnowledgeBaseDocuments.html), and [managed retrieval](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_Retrieve.html) APIs. Exact account support, latency, parser/chunking behavior, and metadata round-trip must be tested with a disposable synthetic object in MVP-08. If Managed KB cannot return stable artifact identity and exact status in the intended account, stop publication and present a costed alternative before changing the retrieval architecture.

## AI exception burden

This PR keeps MVP-05b's source-backed automatic tagging and mock-only routine clearance. The six-unit fictional demo has one automatically eligible unit, one policy-prohibited unit, and four pending units. Publication consumes the one eligible unit without another approval click and never turns the four pending units into clearance. This is a mechanism check, not evidence for the 80% real review-free target or the ten-question three-family target. MVP-09 needs source-checked private labels and a frozen calibration set to widen live automatic clearance safely. The review queue already records automatic and human counts, failure reasons, and review seconds; use those to diagnose any real workload miss before changing policy.
